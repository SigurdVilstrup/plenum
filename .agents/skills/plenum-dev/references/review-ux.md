# UX plan / implementation review

You are reviewing Plenum UX (plan or built flow). Think like a daily user of a Mac git client with lanes.

## Check

1. Task completion: can the user finish the job without reading docs?
2. Next step is obvious after each action (commit, push, conflict, lane start/stop).
3. Friction: extra clicks, modal spam, unclear labels, dead ends.
4. Edge cases: dirty tree, behind/ahead, conflict walk, unprepared worktree vs lane, protected vs feature lane.
5. Keyboard / ⌘K / shortcuts match existing patterns when relevant.
6. Copy is honest and public-repo appropriate (no internal jargon left in the UI).

## Output

- **Blockers**
- **Suggestions**
- **Pass** — one line if clean

Do not implement. Review only.
