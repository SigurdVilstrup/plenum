Lane setup

Why a second checkout cannot start today, and the .plenum/lane.yaml that fixes each one. Nothing is written until you say so.

What the repo does today
Starts through an Aspire AppHosttools/aspire-apphost/apphost.mts, launched with pnpm nx run aspire-apphost:start
Seven fixed portsRavenDB 1338, SQL Edge 1433, Postgres 5432, web 5001, app 5002, api 5055, RideOps 8100. All collide on a second checkout.
Three named Docker volumeslocal-db-environment_ ravendb_data, sqledge_data, postgres_data. Every checkout reads and writes the same data.
Two untracked .env filestools/mobaro-bi, tools/mobaro-docs-mcp/mcp. A new worktree does not get them.
pnpm with a shared storePer-lane install links from .pnpm-store: 1.4 GB the first time, seconds after.
Nx targets for testspnpm nx affected -t test runs only what the lane changed.
Proposed .plenum/lane.yaml
setup:    pnpm install
run:      pnpm nx run aspire-apphost:start   # yours; Plenum calls it
test:     pnpm nx affected -t test
env:
  copy:   [tools/mobaro-bi/.env, tools/mobaro-docs-mcp/mcp/.env]
ports:
  offset: 100          # lane 1: 5101, lane 2: 5201
  expose: { web: 5001, api: 5055 }
services:
  ravendb:  shared       # :1338, one instance
  sqledge:  shared       # :1433
  postgres: shared       # :5432, snapshot available
data:
  snapshot: scripts/db-snapshot.sh
  migrations: apps/backend/deployment/Migrations
Shared data is the default. Lanes get their own ports and processes. The three databases stay the ones you have. Plenum shows this on every lane and checks for migrations the shared database has not run before it starts one.
Agents can run this too: repo.doctor over MCP, or plenum doctor in a shell.

Lane setup lives under Settings › Repositories, in the same window. The doctor reads the repo and proposes a manifest; the user decides what is shared.
